# Quant landing page

The marketing site for Quant: one page that explains what Quant records, who may read it, and how, plus a plain-language privacy page. It is its own [leptoskit](https://github.com/leptoskit/leptoskit) app, web only, with its own Cargo workspace, outside the repository's core workspace, like `apps/quant` and `apps/relay`. The three apps are named in [`leptoskit.workspace.toml`](../../leptoskit.workspace.toml) at the repository root.

The design is "a field notebook for your life": warm paper, confident ink, and skribble's yellow used only as a highlighter. Layout and type live in [`assets/app.css`](assets/app.css); the ink (the highlight, the step circles, the arrows, the day page, the relay diagram) is drawn by [skribble](https://github.com/openbudgetfun/skribble)'s `skribble_leptoskit` and is vector, so there are no images. It follows `prefers-color-scheme` (chalk on charcoal in the dark) and has a toggle, and all motion stops under `prefers-reduced-motion`.

## Layout

| Path                         | What it is                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `landing_app/src/routes/`    | The file router: `index.rs` (`/`), `privacy.rs` (`/privacy`), `+not-found.rs`, and `_layout.rs` (nav, footer) |
| `landing_app/src/routes.rs`  | Generated by `leptoskit plugin:router routes`; committed                                                      |
| `landing_app/src/components/`| One PascalCase `#[component]` per piece of the page, written as `view!` markup                                |
| `landing_app/src/store.rs`   | The page's state in a Leptos store: theme, menu, FAQ answers, and the memory demo                             |
| `landing_app/src/theme.rs`   | The palette the hand-drawn ink is painted with                                                                |
| `assets/app.css`             | Type, layout, and motion, addressed by element id                                                             |
| `src/main.rs`                | The SSR server: renders each URL for its own route, with a 404 for unknown paths                              |

`leptoskit lint` enforces that every capitalised view function is a `#[component]` and that every tree is `view!` markup (see `[lint]` in `leptoskit.toml`).

## Build and run

You need the toolchain in `rust-toolchain.toml` (it includes the Wasm target) and the leptoskit CLI built from the same commit the app pins (see `Cargo.toml`):

```sh
cargo install --git https://github.com/leptoskit/leptoskit --rev <the rev in Cargo.toml> leptoskit_cli
cd apps/landing
leptoskit dev                  # serve with live reload on http://127.0.0.1:3000
leptoskit build --release      # build the server and the client into dist/
leptoskit serve                # serve the release build
```

Checks:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
leptoskit format --toolchain nightly-2026-10-21 --check
leptoskit lint
leptoskit workspace check      # from anywhere in the repository
```

Keep the app on the same Leptoskit commit as the other two: `python3 scripts/update-leptoskit.py` at the repository root pins all three, the relay's and the landing page's Docker build CLI, and the lockfiles together.
Use `--no-check` to resolve the lockfiles and leave compilation and tests to CI.

## Deploy

`leptoskit generate deploy --target fly` wrote the `Dockerfile`, `.dockerignore`, and `fly.toml` here. The server answers `/readyz` and shuts down gracefully, so the same image runs anywhere a container does; run the generator with another `--target` (`compose`, `kubernetes`, or `systemd`) for those files.

```sh
cd apps/landing
fly launch --copy-config --no-deploy   # once, to create the app from fly.toml
fly deploy
```

The `Dockerfile` installs the CLI from the pinned Leptoskit commit rather than crates.io, and `scripts/update-leptoskit.py` keeps that pin current. The site has no database and holds no secrets.

### Browser regression checks

Against a running production build (for example on port 4202):

```sh
npm ci
npx playwright install chromium --only-shell
QUANT_SITE_URL=http://127.0.0.1:4202 npm run test:browser
```

The check covers hydration, theme persistence and drawing layout, the FAQ,
typing and editing a memory correction, direct privacy requests and 404s,
and the mobile menu and horizontal layout. Screenshots are written to
`test-results/` (ignored).
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` can select an existing Chromium executable.

The portable UI uses a store scoped to each SSR render, so visitors never share
interactive state on a server thread. The browser marks completed hydration with
`data-hydrated` for these checks. Generated route compatibility conversions and
the server-function macro's required async signature have narrowly scoped Clippy
exceptions; application code still passes warnings-as-errors.

The `applications` GitHub Actions workflow checks all three app workspaces.
For this site it also installs the pinned SDK CLI, builds the production
server/client, and runs these browser checks with screenshot and server-log
artifacts.

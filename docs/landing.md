# Quant landing page

The public frontend of the Quant application. It explains capture and permissions,
and has a plain-language privacy page. It shares the root Cargo workspace and
`leptoskit.toml`, but has its own routes, public assets, server package and
independent deployment. It has no database or vault credentials.

The design is "a field notebook for your life": warm paper, confident ink, and skribble's yellow used only as a highlighter. Layout and type live in [`assets/landing/app.css`](assets/app.css); the ink (the highlight, the step circles, the arrows, the day page, the relay diagram) is drawn by [skribble](https://github.com/openbudgetfun/skribble)'s `skribble_leptoskit` and is vector, so there are no images. It follows `prefers-color-scheme` (chalk on charcoal in the dark) and has a toggle, and all motion stops under `prefers-reduced-motion`.

## Layout

| Path                         | What it is                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `crates/landing_app/src/routes/`    | The file router: `index.rs` (`/`), `privacy.rs` (`/privacy`), `+not-found.rs`, and `_layout.rs` (nav, footer) |
| `crates/landing_app/src/routes.rs`  | Generated by `leptoskit plugin:router routes`; committed                                                      |
| `crates/landing_app/src/components/`| One PascalCase `#[component]` per piece of the page, written as `view!` markup                                |
| `crates/landing_app/src/store.rs`   | The page's state in a Leptos store: theme, menu, FAQ answers, and the memory demo                             |
| `crates/landing_app/src/theme.rs`   | The palette the hand-drawn ink is painted with                                                                |
| `assets/landing/app.css`             | Type, layout, and motion, addressed by element id                                                             |
| `crates/quant_landing_server/src/main.rs`                | The SSR server: renders each URL for its own route, with a 404 for unknown paths                              |

`leptoskit --app-target landing lint` enforces that every capitalised view function is a `#[component]` and that every tree is `view!` markup (see `[lint]` in `leptoskit.toml`).

## Build and run

You need the toolchain in `rust-toolchain.toml` (it includes the Wasm target) and the leptoskit CLI built from the same commit the app pins (see `Cargo.toml`):

```sh
cargo install --git https://github.com/leptoskit/leptoskit --rev <the rev in Cargo.toml> leptoskit_cli
leptoskit --app-target landing dev                  # serve with live reload on http://127.0.0.1:3000
leptoskit --app-target landing build --release      # build the server and the client into dist/
leptoskit --app-target landing serve                # serve the release build
```

Checks:

```sh
cargo fmt --all --check
cargo clippy -p landing -p landing_app --all-targets -- -D warnings
cargo test -p landing -p landing_app
leptoskit format --toolchain nightly-2026-10-21 --check
leptoskit --app-target landing lint
leptoskit targets      # from anywhere in the repository
```

Keep the app on the same Leptoskit commit throughout the project: `python3 scripts/update-leptoskit.py` at the repository root pins the root manifest, deployment build CLIs and the single lockfile together.
Use `--no-check` to resolve the lockfile and leave compilation and tests to CI.

## Deploy

`leptoskit generate deploy --target fly` wrote the `Dockerfile`, `.dockerignore`, and `fly.toml` here. The server answers `/readyz` and shuts down gracefully, so the same image runs anywhere a container does; run the generator with another `--target` (`compose`, `kubernetes`, or `systemd`) for those files.

```sh
fly launch --config deploy/landing/fly.toml --copy-config --no-deploy   # once, to create the app from fly.toml
fly deploy --config deploy/landing/fly.toml
```

The `Dockerfile` installs the CLI from the pinned Leptoskit commit rather than crates.io, and `scripts/update-leptoskit.py` keeps that pin current. The site has no database and holds no secrets.

### Browser regression checks

Against a running production build (for example on port 4202):

```sh
npm ci
npx playwright install chromium --only-shell
QUANT_SITE_URL=http://127.0.0.1:4202 npm run test:browser
```

The check covers hydration, theme persistence and drawing layout, the FAQ,
typing and editing a memory correction, direct privacy requests and 404s,
and the mobile menu and horizontal layout. Screenshots are written to
`test-results/` (ignored).
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` can select an existing Chromium executable.

The portable UI uses a store scoped to each SSR render, so visitors never share
interactive state on a server thread. The browser marks completed hydration with
`data-hydrated` for these checks. Generated route compatibility conversions and
the server-function macro's required async signature have narrowly scoped Clippy
exceptions; application code still passes warnings-as-errors.

The `application-targets` GitHub Actions workflow checks the desktop, relay and landing packages in the single Cargo workspace.
For this site it also installs the pinned SDK CLI, builds the production
server/client, and runs these browser checks with screenshot and server-log
artifacts.
